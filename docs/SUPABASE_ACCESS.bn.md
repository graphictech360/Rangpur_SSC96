# Supabase-এর পুরো কাজ কে করবে, কী অ্যাক্সেস লাগবে, আর key কীভাবে বদলাবেন

## সংক্ষেপে দুটি উত্তর

**১) আপনার প্রশ্ন: “তুমি সবকিছু করবে — এর জন্য কী কী অ্যাক্সেস লাগবে?”**

দরকার শুধু একটি জিনিস: **একটি সীমিত-ক্ষমতার Personal Access Token (PAT)**।
আর লাগে **না**: service_role/secret key, ডেটাবেসের পাসওয়ার্ড, আপনার Supabase অ্যাকাউন্টের লগইন পাসওয়ার্ড, OTP — এগুলোর কোনোটিই কখনো দেবেন না।

**২) আপনার প্রশ্ন: “কাজ শেষে Supabase থেকে সব key বদলাতে পারব?”**

**হ্যাঁ, পুরোপুরি পারবেন — এবং বদলানোই উচিত।** টেবিল, ডেটা, QR টিকিট, নিয়ম (RLS) কিছুই নষ্ট হবে না। শুধু বদলানোর পর হোস্টিং-এর `.env`-এ নতুন key বসিয়ে redeploy করতে হবে। বিস্তারিত শেষে।

## পথ ১ — আমি (এই এজেন্ট) পুরো কাজ করব

### ১. যে টোকেনটি লাগবে

Supabase → **Account → Access Tokens → Generate new token**

- নাম দিন: যেমন `ssc96-setup`
- মেয়াদ: সবচেয়ে কম (১ দিন) — কাজ শেষেই বাতিল করবেন
- **Project access:** শুধু `Rangpur_SSC96` প্রকল্প
- **Scopes (ক্ষমতা):**

| Scope                                     | কেন লাগবে                                                                       |
| ----------------------------------------- | ------------------------------------------------------------------------------- |
| `database:read`                           | টেবিল/নীতি/ডেটা যাচাই করতে                                                      |
| `database:write`                          | ১৪টি টেবিল, RLS, RPC ও seed তৈরি করতে                                           |
| `auth:read` _(ঐচ্ছিক)_                    | আপনার অ্যাকাউন্ট আছে কি না মিলিয়ে দেখতে                                        |
| `auth:write` _(ঐচ্ছিক, সাধারণত লাগবে না)_ | **নিজের ইচ্ছায়** অ্যাকাউন্ট বানানো; তবে পাসওয়ার্ড আপনার নিজের হাতে থাকাই ভালো |
| `projects:read`                           | প্রকল্প খুঁজে পেতে (না দিলেও চলে)                                               |

### ২. টোকেনটি আমাকে দিলে আমি যা চালাব

```
SUPABASE_ACCESS_TOKEN=<আপনার টোকেন> node scripts/supabase-apply.mjs \
   --ref mbuzwqsrnmergrtetwqq \
   --admin you@example.com \
   --staff gate1@example.com --staff gate2@example.com
```

স্ক্রিপ্টটি ধাপে ধাপে:

1. `supabase/01_schema.sql` — **১৪টি টেবিল**, RLS, ৯টি RPC, গ্রান্ট/রিভোক নিয়ম
2. `supabase/02_seed.sql` — ইভেন্ট, **১৩ কনটেন্ট**, **১৪ সময়সূচি**, **৮ পেমেন্ট নম্বর** (কোনো নমুনা ব্যক্তি/পেমেন্ট নয়)
3. আপনার ইমেইল দিয়ে **অ্যাডমিন ভূমিকা**, স্টাফ ইমেইলগুলো দিয়ে **scanner ভূমিকা** বসানো — _পাসওয়ার্ড আমি কখনো পড়ি না বা লিখি না; অ্যাকাউন্টগুলো আপনি Dashboard-এ বানাবেন_
4. যাচাই: টেবিল সংখ্যা, RLS চালু, policy, ফাংশন, সিড ডেটা, `anon` কেবল অনুমোদিত RPC চালাতে পারে কি না, আর `ssc96` স্কিমা Data API-তে খোলা পড়ে আছে কি না

শেষে স্ক্রিনে যা দেখবেন (আনুমানিক):

```
টেবিল: 14 (RLS চালু: 14, policy: 18)
SECURITY DEFINER ফাংশন: 14
সিড ডেটা → কনটেন্ট 13, সময়সূচি 14, পেমেন্ট নম্বর 8, অংশগ্রহণকারী 0
anon → public_site: অনুমোদিত ✅ | সরাসরি participants পড়া: নিষিদ্ধ ✅
```

### ৩. আমার হাতে টোকেন শুধু এই কাজের জন্যই

- আমি টোকেন **কোথাও মেসেজে ফিরিয়ে লিখব না, লগ করব না, ফাইলে রাখব না**।
- কাজ শেষে আপনি পাকা করুন: **Access Tokens → টোকেনটি Revoke** (এক ক্লিক)। বাতিল করলে অ্যাপ বা ডেটাবেসে কোনো প্রভাব পড়ে না।
- অ্যাপ চলার জন্য টোকেন **লাগেই না** — অ্যাপ চলে শুধু publishable/anon key দিয়ে, যা প্রকাশ্য হওয়ার জন্যই বানানো।

### ৪. অ্যাকাউন্ট তৈরির নিরাপদ নিয়ম

- **পাসওয়ার্ড শুধু আপনি বানাবেন** (Dashboard → Authentication → Users → Add user) এবং বন্ধুদের সঙ্গে সরাসরি ভাগ করবেন; চ্যাটে নয়।
- তারপর শুধু ইমেইল দিলে আমি/all-in-one স্ক্রিপ্ট ভূমিকা বসিয়ে দেবে।
- চাইলে আপনার Toufiq/নিজের ইমেইল আগেই বানিয়ে রাখুন — তাহলে এক ধাপেই সব শেষ।

### ৫. এই পথে না গেলে — সবচেয়ে সহজ বিকল্প (টোকেন ছাড়াই)

`supabase/04_SETUP_ALL_IN_ONE.sql` ফাইলটি Supabase **SQL Editor**-এ পেস্ট করে **Run** — ২ মিনিটেই টেবিল+নীতি+seed তৈরি।
এরপর Dashboard-এ নিজের অ্যাকাউন্ট বানিয়ে `supabase/03_staff_setup.sql`-এ নিজের ইমেইল বসিয়ে চালান। আমাকে টোকেন দিতে হবে না।

## কাজ শেষে key বদলানো — কী বদলাবেন, কী বদলাবে না

### হ্যাঁ, যা যা বদলাতে পারবেন (সুপারিশ করা হয়)

| #   | Key                               | কোথায় বদলাবেন                                          | বদলানোর পর কী করতে হবে                                    | প্রভাব                                                                            |
| --- | --------------------------------- | ------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------- |
| ১   | **Personal Access Token**         | Account → Access Tokens → Revoke                        | কিছুই না                                                  | আপনার অটোমেশন বন্ধ হবে, অ্যাপ চলবে                                                |
| ২   | **Publishable / anon key**        | Project Settings → API → rotate                         | হোস্টিংয়ের `SUPABASE_PUBLISHABLE_KEY` আপডেট করে redeploy | অ্যাপ আবার অনলাইন; পুরোনো key আর কাজ করবে না                                      |
| ৩   | **JWT signing key / secret**      | Project Settings → API → JWT Settings → rotate          | উপরের মতোই নতুন anon/service key বসাতে হবে                | সব পুরোনো টোকেন বাতিল; **আগে anon key আপডেটের প্রস্তুতি নিয়ে** তারপর rotate করুন |
| ৪   | **Database password**             | Settings → Database → Reset password                    | কিছুই না (অ্যাপ এটি ব্যবহার করে না)                       | ডেটাবেসে কোনো পরিবর্তন হয় না                                                     |
| ৫   | **স্টাফদের পাসওয়ার্ড**           | Authentication → Users → Reset/Update                   | ওই ব্যক্তিকে নতুন পাসওয়ার্ড দিন                          | অনুমোদিত ডিভাইস ও টিকিট অপরিবর্তিত                                                |
| ৬   | **`SESSION_SECRET`** (এই অ্যাপের) | হোস্টিং env                                             | redeploy                                                  | সবাইকে আবার লগইন করতে হবে (সেশন নতুন করে)                                         |
| ৭   | **আয়োজক/স্টাফ বাতিল**            | `ssc96.staff_roles.is_active=false` বা অ্যাডমিন প্যানেল | ওই ব্যক্তির ব্রাউজার ডিভাইস revoke                        | লগইন/স্ক্যান বন্ধ, ডেটা অপরিবর্তিত                                                |

### যা বদলাবে না (নিশ্চিন্ত থাকুন)

- ✅ ১৪টি টেবিল, সব লাইন-আপ (নিবন্ধন, পেমেন্ট রেকর্ড, চেক-ইন), কনটেন্ট, সময়সূচি
- ✅ প্রতিটি অংশগ্রহণকারীর **টিকিট নম্বর ও QR** (QR গোপন কী আপনার ডেটাবেসেই থাকে)
- ✅ Supabase project URL, RLS নিয়ম, RPC, ভূমিকা
- ✅ ব্যানারের ছবি/ফন্ট — এগুলো অ্যাপের ভেতরে, Supabase-এ নয়

### মনে রাখার ৩টি নিয়ম

1. **একসাথে একটির বেশি নয়** — anon key rotate করলে সাথে সাথেই হোস্টিং env আপডেট করুন; নইলে ততক্ষণ অ্যাপ "সংযোগ হচ্ছে না" দেখাবে।
2. **`service_role`/secret key কখনো অ্যাপে বা হোস্টিং env-এ দেবেন না** — এই অ্যাপ ইচ্ছা করেই সেটি প্রত্যাখ্যান করে। তাতে কেউ পুরো ডেটাবেস পড়ার ঝুঁকি নেই।
3. **rotate করার আগে Backup** — Settings → Database → Backups (এবং panel থেকে CSV) একবার নিয়ে রাখুন।

## আপনার পরের ধাপ (যেটা একটুর জন্য বাকি)

1. Supabase → Account → Access Tokens → ওপরে দেওয়া scope-এ টোকেন বানান (১ দিন মেয়াদ)।
2. টোকেন + আপনার অ্যাডমিন ইমেইল চ্যাটে দিন (স্টাফ ইমেইলও থাকলে দিন)।
3. আমি স্ক্রিপ্ট চালিয়ে ১৪ টেবিল + সিড + ভূমিকা বসিয়ে, যাচাইয়ের রিপোর্ট দেখাব।
4. আপনি টোকেন **Revoke** করবেন।
5. হোস্টিং (Render ইত্যাদি)-এ `DATA_MODE=supabase` আর publishable key বসিয়ে লিংক চালু করব — সেটাই সবার পাবলিক লিংক।
